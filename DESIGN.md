# Velune Design System

## Overview

### Creative North Star

Velune ощущается как спокойный ночной пульт управления стримом: тёмные матовые поверхности, лавандовые сигналы и точечные индикаторы состояния. Выразительность сосредоточена в музыкальном виджете, темах и фирменных деталях; настройки остаются тихими и практичными.

### Product context and register

- **Аудитория и задача:** русскоязычный стример на Windows настраивает отображение музыки в OBS и локальные интеграции.
- **Локаль:** интерфейс и документация на русском; технические названия OBS и Streamer.bot сохраняются без перевода.
- **Сцена:** настольное приложение, обычно открыто во время настройки перед эфиром и затем свёрнуто в трей.
- **Регистр:** продуктовый интерфейс с умеренной фирменной выразительностью.
- **Запоминающаяся деталь:** лавандовые сигнальные элементы, пиксельная тема Neko и локальный CSS-редактор для авторского оформления.
- **Сдержанность:** формы, ссылки и инструкции должны читаться быстрее декоративных деталей.
- **Не использовать:** яркие корпоративные дашборды, стеклянные панели с сильным blur, декоративные градиенты на каждом элементе.
- **Источник токенов:** этот файл отражает канонические значения встроенных стилей `static/index.html`; при изменении системных цветов или геометрии обновляются оба файла.

## Colors

`background` задаёт общий фон, `surface` — карточки, `surface-deep` — поля и внутренние панели. `primary` используется для главных действий и выбранных состояний, `success` — только для подтверждённого подключения. Приглушённый текст не должен использоваться для критичных инструкций.

## Typography

Основной стек — Segoe UI с системным fallback. Pixel применяется только в теме Neko и никогда для длинных инструкций. Заголовки используют умеренный вес 600; технические URL и переменные допускают Consolas/monospace.

## Layout

Максимальная ширина — 1200 px. Рабочая область использует левую колонку источника и оформления и гибкую правую колонку предпросмотра и экспорта. Ниже 680 px всё переходит в одну колонку без горизонтального скролла. Блоки интеграций продолжают вертикальный сценарий после OBS.

## Elevation & Depth

Иерархия строится тональными слоями и границами, без теней у обычных карточек. Декоративные кольца допустимы только как фоновая метафора соединения и не должны пересекать текст или элементы управления.

## Shapes

Карточки имеют радиус 20 px, поля и кнопки — 10 px, компактные переключатели — 8 px. Круги применяются для статусов, палитр и фирменной графики.

## Components

### Foundational visual states

Интерактивные элементы сохраняют нативный `focus-visible` с внешним отступом. Выбранные состояния обозначаются цветом границы и фона, отключённые — сниженной непрозрачностью. Успех и ошибки сообщаются текстом в `aria-live`, не только цветом.

### Buttons and actions

Лавандовая заливка обозначает основное действие копирования. Вторичные действия используют тёмную поверхность с границей. Текст кнопки описывает результат: «Копировать», «Свернуть в фон».

### Navigation and data display

Экран линейный; номера 01–05 показывают реальный порядок настройки: источник, стиль, OBS, пользовательский CSS, Streamer.bot.

### Forms and overlays

Поля имеют видимые labels. Read-only URL остаётся выделяемым и получает fallback-инструкцию Ctrl+C, если Clipboard API недоступен. CSS-редактор использует моноширинный шрифт, допускает вертикальное изменение размера и связывается с подсказкой селекторов через `aria-describedby`.

### Iconography

Используются простые символы и фирменные SVG/PNG. У значимых icon-only кнопок обязательны `aria-label` и `title`.

### Motion

Анимация разрешена только для RGB-перелива логотипа автора и отключается через `prefers-reduced-motion`.

### Content and data visualization

Тон дружелюбный и прямой. Инструкции называют точные пункты меню стороннего приложения и показывают реальные переменные, например `%veluneSong%`.

## Do's and Don'ts

- **Do:** продолжать лавандовую сигнальную метафору для подключений и экспорта.
- **Do:** показывать готовые значения для копирования и короткий путь настройки.
- **Don't:** скрывать обязательные шаги подключения только во внешней документации.
- **Don't:** добавлять декоративные эффекты, ухудшающие чтение технических URL и статусов.
