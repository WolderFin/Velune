# Подпись Windows и антивирусные срабатывания

## Текущее состояние 1.0.0

`Velune.exe` — переносимое приложение, а не установщик. Текущая локальная сборка не подписана Authenticode. Поэтому SmartScreen показывает «Windows защитила компьютер», а корпоративная политика может полностью запретить запуск. Самоподписанный сертификат для публичной раздачи проблему не решает.

Однофайловая сборка PyInstaller содержит интерпретатор Python и библиотеки и распаковывает их при запуске. Такое устройство вместе с отсутствием репутации и подписи часто попадает под общие статические эвристики. Это объясняет возможную причину, но само по себе не доказывает ложное срабатывание.

Совпадение нескольких ML/эвристических движков важно и требует проверки. Оно не равно шести независимым подтверждениям одного семейства: названия не согласуются и не описывают единую вредоносную функцию. Для каждого нового бинарника повторяйте сканирование; вывод относится только к конкретному SHA-256.

## Что проверено в исходниках

- сервер привязан только к loopback `127.0.0.1`;
- внешних загрузок, запуска команд, PowerShell, `subprocess`, автозагрузки и записи в реестр нет;
- `ctypes` используется для AppUserModelID и сообщения Windows;
- приложение читает Windows Media Session, показывает локальный WebView и значок трея;
- зависимости зафиксированы в `requirements-lock.txt`, их лицензии перечислены в `THIRD_PARTY_NOTICES.md`.

Публичный исходный код облегчает аудит, но не доказывает, что скачанный EXE собран именно из него. Поэтому релизу нужны подпись, SHA-256 и сборка через публичный GitHub Actions workflow.

## Правильная подпись

Предпочтительные варианты:

1. Публикация через Microsoft Store — пакет переподписывается Microsoft и не получает предупреждение SmartScreen о загрузке.
2. Microsoft Artifact Signing либо сертификат code signing OV/EV от доверенного центра. Для каждого релиза используйте одну и ту же подтверждённую личность издателя и RFC 3161 timestamp.

Даже доверенная OV/EV-подпись не гарантирует отсутствие предупреждения у первых загрузок: SmartScreen учитывает также репутацию нового файла и издателя. EV больше не даёт автоматического обхода SmartScreen. Подпись всё равно важна: показывает проверенного издателя, защищает целостность и переносит репутацию между релизами.

Локальный сценарий после получения сертификата в Windows Certificate Store:

```powershell
.\scripts\sign_release.ps1 -CertificateThumbprint 'THUMBPRINT'
py -3.14 scripts\package_release.py
py -3.14 scripts\write_checksums.py
```

Никогда не добавляйте PFX, пароль, токен Artifact Signing или иные секреты в Git. Для CI используйте GitHub Secrets/OIDC и официальный action выбранного сервиса. Сначала подпишите `Velune.exe`, затем создайте ZIP: изменение файла после подписи делает подпись недействительной.

## Оспаривание детектов

Перед отправкой сохраните точный SHA-256, ссылку на официальный Release и VirusTotal, версию программы, снимок детектов и статус подписи. Microsoft принимает ложные срабатывания на <https://www.microsoft.com/en-us/wdsi/filesubmission>: выберите **Software developer** и **Incorrectly detected as malware**, укажите `Trojan:Win32/Wacatac.C!ml` и приложите EXE. Для остальных движков используйте официальные формы поддержки каждого вендора или контакты из раздела Vendor contacts в VirusTotal.

Не просите пользователей отключать Defender или добавлять постоянное исключение. До решения лаборатории безопаснее предоставить исходники и контрольную сумму, а выпуск пометить как неподписанный.
